# CLR Execution Flow

Use this page for assemblies, IL, the CLR startup path, and JIT compilation.

## Most Important FAQ

### What is the CLR execution flow?

C# code is compiled into IL inside an assembly. At runtime, the CLR loads the assembly, verifies IL, JIT-compiles needed methods into native code, and executes them.

### What is JIT?

JIT compilation converts IL into native machine code at runtime, usually method by method when needed.

## Quick Map

### Assembly

Short version: Compiled `.dll` or `.exe` containing IL, metadata, and a manifest.

### IL

Short version: Platform-neutral intermediate code generated by .NET compilers.

### CLR

Short version: Execution engine that loads, verifies, runs, and services .NET code.

### JIT

Short version: Converts IL into native machine code at runtime, usually method by method.

## What Is An Assembly?

In C# and the .NET ecosystem, an assembly is a compiled output file, typically a `.dll` or `.exe`, that serves as the fundamental building block of an application. It represents the smallest single unit of deployment, execution, version control, and security permissions for any .NET project.

When you write code in C# and build your project, the compiler does not create machine code immediately. Instead, it bundles your classes, interfaces, and logic into an assembly containing Common Intermediate Language (CIL) code, which the .NET runtime later executes.

## Explain CLR Execution Flow

**Interview answer:** When I build a .NET application, the Roslyn compiler compiles the C# source code into an assembly, `.dll` or `.exe`, containing Intermediate Language (IL), metadata, and a manifest. At runtime, the .NET host loads the CLR, which loads the assembly and verifies the IL for type safety. The CLR then loads types and methods on demand.

When a method is invoked for the first time, the Just-In-Time (JIT) compiler translates that method's IL into native machine code specific to the current operating system and CPU architecture. This native code is cached in memory, so subsequent calls execute the already compiled machine code without invoking the JIT again.

Throughout the application's lifetime, the CLR provides runtime services such as garbage collection, exception handling, thread management, security checks, and interoperability with native code.

### Execution Pipeline

```text
C# source
  -> Roslyn compiler
  -> Assembly (.dll/.exe)
  -> IL + metadata + manifest
  -> CLR
  -> JIT
  -> Native code
  -> CPU
```

This sequence, from Roslyn to IL to CLR to JIT to native code to CPU, is exactly what most interviewers expect for a solid explanation of the .NET execution pipeline.

## What Is IL Code?

IL, or Intermediate Language, is the CPU-agnostic code that .NET compilers generate from your source code. Instead of going straight to machine code, your C# or other .NET language is compiled into IL. This IL is then stored in the assembly.

When you run your program, the runtime's Just-In-Time compiler translates that IL into machine code specific to the platform. So IL is a universal intermediate step that makes your code portable across platforms.

## What Is JIT Compilation?

**Interview answer:** JIT is the component of the CLR that converts IL into native machine code at runtime. It compiles methods on first use, not the entire application, which reduces startup time. Once a method is JIT-compiled, the generated native code is reused for subsequent calls.

Just-in-Time (JIT) compilation is when the intermediate language (IL) is converted into machine code right before execution, at runtime, method by method. We do this so the program stays platform-independent until it is run, making it flexible across systems. It also speeds up the initial build process, since you do not have to compile everything upfront. Plus, the JIT can optimize the code specifically for the exact machine it is running on, taking advantage of the hardware in ways a one-size-fits-all ahead-of-time compilation might not.

Just-in-Time (JIT) compilation is when the intermediate language (IL) gets converted into machine code at the moment you need it, right before a method runs. Instead of converting the entire program to machine code beforehand, the JIT compiles each method the first time it is called. At runtime, the JIT takes IL instructions and turns them into fast, native instructions that the CPU can execute. In short: JIT means the final machine code is generated "just in time", only as needed, on the fly.

The JIT waits until the program is running on a specific machine, and then it creates the machine code that fits that platform exactly. Instead of creating separate platform-specific builds ahead of time, you compile once into IL and let the JIT handle making the final, platform-specific code right when it is needed.

When you call a method for the first time, the JIT compiles it. If that method calls another method that has not been run yet, the JIT will compile that new method the first time it is invoked. Over time, as you run more of your code, the JIT compiles the methods you actually use. But if a method never gets called, it never gets compiled. It is a step-by-step, on-demand process as execution flows, balancing performance and startup cost.

## Common Interview Follow-Ups

### What is the difference between CLR and .NET Runtime?

Answer: The CLR is the execution engine. The .NET runtime includes the CLR plus the base class libraries and other runtime components.

### Why use IL instead of compiling directly to machine code?

Answer: IL is CPU-independent, enabling the same assembly to run on different architectures such as Windows, Linux, macOS, x64, and ARM with platform-specific JIT compilation.

### What is the difference between IL and machine code?

Answer: IL is an intermediate, platform-neutral instruction set. Machine code is CPU-specific binary instructions executed directly by the processor.

### Can the CLR execute C++ code?

Answer: Native C++ runs outside the CLR. C++/CLI can target the CLR by compiling to IL.

### When does JIT happen?

Answer: Typically on the first invocation of each method.

### What happens if a method is never called?

Answer: It generally will not be JIT-compiled.

### Why use JIT instead of compiling everything beforehand?

Answer: IL is platform-independent. The same assembly can run on Windows, Linux, or macOS. At runtime, the JIT generates optimized machine code for the specific CPU architecture, such as x64 or ARM64, and can apply runtime optimizations based on the actual execution environment.
